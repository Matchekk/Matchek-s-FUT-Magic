# GrindPilot FC26 v2.2 HEAD audit

Audit date: 2026-08-25
Audited commit: `22b15ff` (`codex/grindpilot-mvp`, version 2.1.2)
Implementation branch: `codex/v2.2-production`

## Method and baseline

The audit covered every tracked file under `src/`, `page/`, `solver/`, and
`test/`, plus the extension bootstrap, service worker, manifest, package
scripts, required documentation, and GitHub Actions. Runtime wiring was traced
from `content-script.js` through `src/grindpilot-main.js`, the controller bridge
in `page/ea-data-bridge.js`, and the legacy solver request path.

Baseline results:

- `npm test`: **WORKING** — 139/139 tests passed.
- `npm run check`: **WORKING** — syntax, manifest, assets, and privilege checks
  passed.
- GitHub Actions: **PARTIALLY_WIRED** — it runs the two required baseline
  commands, but no browser harness or package build.
- Version alignment: **WORKING** — package and manifest are both 2.1.2.

Classification meanings used below:

- `WORKING`: production path is wired and covered by meaningful automated
  tests.
- `PARTIALLY_WIRED`: useful code exists and some production path uses it, but
  the advertised behavior is incomplete.
- `DORMANT`: implementation exists but the production runtime does not call it.
- `BROKEN`: a reachable path contradicts its intended behavior or acceptance
  criteria.
- `UNVERIFIED_LIVE`: implementation or mocks exist, but current EA Web App
  behavior has not been manually verified.
- `TECH_DEBT`: maintainability or verification debt without a confirmed current
  functional failure.

## Important runtime findings

1. `GrindPilotRuntime` constructs `FodderPolicy`, but sends only a protected-ID
   list and three preference booleans to the live page bridge. The richer
   objective is currently descriptive, not a production selection objective.
2. `ExistingAutoPilotSolver` is a tested adapter that reports a policy tuple,
   but the production page path calls `callSolveBridge()` directly and never
   instantiates that adapter.
3. `PlayerPickService` is never imported by the runtime. The bridge returns
   `pending` and pick item IDs only; `selectPlayerPick` is deliberately
   unavailable.
4. Target Projects already normalize the requested domain fields, yet the UI
   discards almost all of them during creation and offers no edit/sync/import.
5. The live unassigned resolver duplicates logic that already exists in
   `resolution-policy.js`, increasing drift risk around tradable duplicates and
   storage eligibility.
6. The legacy bridge remains the only place with controller-closure access.
   v2.2 should add narrow GrindPilot functions there and keep domain decisions
   in `src/`; a large extraction would be destabilizing.

## v2.2 implementation direction

The release should preserve the existing WorkflowEngine and controller bridge,
then close the wiring gaps through small injected capabilities and testable
domain modules. Any EA field that cannot be observed reliably must remain
unknown and force pause for destructive behavior. Mock/replay success must not
be described as live EA verification.
